# EXP-000: E0, the production GenPhenia v3.0 baseline

- **Front:** shared (the reference for both fronts)
- **Registered:** 2026-09-28, by Mateo Alvarez
- **Status:** planned

## Hypothesis
Descriptive, not confirmatory: measure production v3.0 on every cohort with the
shared harness, so that every later claim is a paired Δ against these exact
per-case ranks.

## Systems compared
| System | Artifact ids / code | Notes |
|---|---|---|
| E0 | source `genphenia_v3` (model-v3.0.0, tarball sha256 `2201b7f2…`) via `systems/genphenia_v3.py` | Bit-identical to the vendored production engine on 300 R1-train cases (max \|Δp\| = 0); matches the production-captured top-10 to ≤ 5e-7 |

## Data
- **No training.** v3.0 is used as released.
- **Free runs:** `r1-v1/train`, `r1-v1/dev`, `s2`.
- **Sealed reads, one each, reason "E0 reference":** `r1-v1/test`, `mcrd`,
  `ddd`.
- **The vault is not opened.** It is reserved for the final report
  (EVAL_PROTOCOL §2).

## Views
- v3.0 ignores excluded terms, sex and age, so every view must give identical
  ranks.
- On dev both `present` and `all` are run as a check of that invariant.
- Elsewhere only `all` is run.

## Primary metric and gate
- **Primary metric:** R1 MRR (pessimistic tie ranks; an unrankable case counts
  as a miss).
- **Gate:** none, since this is the baseline. It is accepted if:
  - the parity tests pass;
  - dev `present` == `all`, case by case.
- **Expectations written before running**, to catch a broken harness, not to
  judge the model:

  | Cohort | Expected range | Basis |
  |---|---|---|
  | R1 MRR | 0.40–0.60 | qa-agent measured 0.508 on 501 phenopacket patients, one per gene |
  | S2 top-1 | 0.5–0.8 | in-distribution simulation; v3.0 validation top-1 was 0.711 |
  | MCRD | low, possibly < 0.2 | an older checkpoint scored 0.070 |

## Dev search
None: nothing is tuned.

## Known caveat
E0 on R1 is optimistic. v3.0's training data came from `genes_to_phenotype`,
which includes annotations from R1 publications (EVAL_PROTOCOL §4.5).
