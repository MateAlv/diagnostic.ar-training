# EXP-000: E0, the production GenPhenia v3.0 baseline

- **Front:** shared (the reference for both fronts)
- **Registered:** 2026-09-28, by Mateo Alvarez
- **Status:** done (2026-09-29)

## Hypothesis
Descriptive, not confirmatory: measure production v3.0 on every cohort with the
shared harness, so that every later claim is a paired Δ against these exact
per-case ranks.

| System | Artifact ids / code | Notes |

## Data
- **No training.** v3.0 is used as released.
- **Free runs:** `r1-v1/train`, `r1-v1/dev`, `s2`.
- **Sealed reads, one each, reason "E0 reference":** `r1-v1/test`, `mcrd`,
  `ddd`.
- **The vault is not opened.** It is reserved for the final report
  (EVAL_PROTOCOL §2).

## Views
- v3.0 ignores excluded terms, sex and age, so every view must give identical
  ranks.
- On dev both `present` and `all` are run as a check of that invariant.
- Elsewhere only `all` is run.

## Primary metric and gate
- **Primary metric:** R1 MRR (pessimistic tie ranks; an unrankable case counts
  as a miss).
- **Gate:** none, since this is the baseline. It is accepted if:
  - the parity tests pass;
  - dev `present` == `all`, case by case.
- **Expectations written before running**, to catch a broken harness, not to
  judge the model:

  | Cohort | Expected range | Basis |
  |---|---|---|
  | R1 MRR | 0.40–0.60 | qa-agent measured 0.508 on 501 phenopacket patients, one per gene |
  | S2 top-1 | 0.5–0.8 | in-distribution simulation; v3.0 validation top-1 was 0.711 |
  | MCRD | low, possibly < 0.2 | an older checkpoint scored 0.070 |

## Dev search
None: nothing is tuned.

## Known caveat
E0 on R1 is optimistic. v3.0's training data came from `genes_to_phenotype`,
which includes annotations from R1 publications (EVAL_PROTOCOL §4.5).

## Addenda

### 2026-09-29, Addendum 1: benchmark provenance (post-hoc, exploratory)
The MCRD result broke the expectation, so each cohort's cases were compared
with the gene's own HPO annotations (HPO 2026-02-16 `genes_to_phenotype`).
This was a content audit of data already opened for this experiment; no model
was changed.

| Cohort | Terms per case (median) | Case terms annotated to the gene (median) | Fully annotated cases | Cases with an inheritance-mode term (HP:0000005 subtree) |
|---|---|---|---|---|
| MCRD | 7 | 0.37 | 3.5% | 0.0% |
| DDD | 18 | 1.00 | 54.4% | **97.1%** |
| R1-dev | 8 | 1.00 | 78.1% | 0.0% |
| R1-train | 7 | 1.00 | 68.2% | 0.0% |

What this shows:
- **DDD cases look derived from annotation profiles.** Real patients don't
  carry "autosomal dominant inheritance" as a phenotype, and v3.0 was trained
  on `genes_to_phenotype`, which contains these terms. DDD therefore
  **overstates real-patient performance**. It is kept only as a no-regression
  check, never as evidence of clinical accuracy.
- **MCRD looks like genuine patients** (terms mostly not verbatim
  annotations), and v3.0 does well on it.
- **The earlier MCRD MRR of 0.070** (GraPhens `validation_arena` CSV, 2025-06,
  unknown checkpoint) most likely came from a broken model or gene order. An
  upstream `genes.json.bak_wrong_order` exists. This cannot be verified.
- **R1 patients' terms are verbatim HPO annotations far more often than
  MCRD's.** This is consistent with HPOA having been curated from these same
  papers, and it quantifies the E0 optimism already declared
  (EVAL_PROTOCOL §4.5).

### 2026-09-29, Addendum 2: confidence intervals on R1 must resample publications
Patients cluster heavily by publication. The largest publication holds 18.1%
of R1-test (462 patients), 7.2% of dev and 8.1% of train.

| Part | Case-bootstrap MRR CI | Publication-bootstrap MRR CI |
|---|---|---|
| train | [0.426, 0.454] | [0.385, 0.491] |
| dev | [0.430, 0.467] | [0.398, 0.501] |
| test | [0.354, 0.386] | [0.269, 0.483] |

The case bootstrap understates uncertainty 3–7×. As a result:
- `metrics.paired_bootstrap` resamples groups when given them;
- R1 runs record each case's publication group;
- the R1 CIs above come from `dxt eval cluster-summaries EXP-000`, which
  derives them from the existing rank files, with no new read.

The dev → test MRR drop (0.448 → 0.370) lies within publication-level
variability.

### 2026-09-29, Addendum 3: the gene vocabulary limits every front built on v3.0
10.6–14.2% of R1 patients have a causal gene outside v3.0's 5,229 classes.
Across train and dev that is 86 genes and 784 patients, and 70 of those genes
are in HPO 2026-02-16 `genes_to_phenotype`. HPO 2026 has 145 genes v3.0
cannot output. No re-ranker over v3.0 can recover these cases; Front A could,
by adding warm-started classifier rows. This is proposed as a decision, not
adopted (see `docs/BITACORA.md`).
