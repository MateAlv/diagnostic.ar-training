# EXP-S3-001: negation as the app produces it, on simulated patients (S3-dev)

- **Front:** B (and the S3 harness itself)
- **Registered:** 2026-09-29, by Mateo Alvarez
- **Status:** done (2026-09-29)

## Hypothesis
On patients whose true phenotype is known, and with negated findings produced
the way the app produces them:
- **(H1)** the questioner's answers improve E0;
- **(H2)** rr-v1's clinically signed negation feature improves on E0 with
  answers;
- **(H3)** rr-v2's R1-learned weights, which reward genes that annotate
  denied findings, *hurt*.

## Design (EVAL_PROTOCOL §8; all leakage guards enforced by `dxt s3 run`)
- **Patients:** `s3-data-v1`, 20,200 cases (4 per gene × 5,050 genes).
  - Generated from the **full** profiles (A ∪ B, R1 held-out PMIDs masked)
    with `simcal-s3-v1`, simulator@b592224, seed 2002.
  - Split `s3-v1` (content `d608574c…`), frozen before any system ran. This
    experiment reads **S3-dev (10,210 cases) only**; S3-test stays sealed.
- **Systems' knowledge:** `kb-v5` (half B of `annot-split-v1` dropped). The
  command refuses any KB whose manifest doesn't say so.
- **Questioner:**
  - sees a `PublicCase` only (reported present terms, sex, age, onset);
  - asks Q = 7 terms, chosen by information gain over E0's top-10 genes,
    with P(t | gene) from `kb-v5`;
  - never asks a reported term or its relatives;
  - is non-adaptive.
- **Answers** come from `true_present` only: "yes" when the term is true or
  an ancestor of a true term.
- **Inputs:** every system gets the same interviewed case: reported present
  + "yes" answers as present, "no" answers as excluded, and sex, age and
  onset as reported.
- **CIs:** paired bootstrap resampling **genes** (4 patients per gene are
  not independent).

## Systems (budget: 8, all reported)
| Name | What |
|---|---|
| E0-initial | v3.0 on the initial presentation (no questions) |
| **E0+answers** | v3.0 on present + "yes" answers. **The reference for every Δ** |
| rr-v1[neg=0.5], rr-v1[neg=1], rr-v1[neg=2] | Negation feature only (`neg_llr`, k = 0.5), clinical sign |
| rr-v1[all=1] | All four rr-v1 features at weight 1 |
| rr-v2[EXP-B-002 l2=0.1] | β fitted on R1-train (EXP-B-002) |
| rr-v2[without negation] | β refitted on R1-train without the negation components (EXP-B-002 ablation) |

## Primary metric and decision rules
- **Primary:** Δ MRR vs E0+answers on S3-dev.
- **H1:** E0-initial vs E0+answers; expected Δ < 0 for E0-initial.
- **H2:** the best `neg` weight, selected on S3-dev among {0.5, 1, 2}.
  Supported if its CI lower bound > 0 and harmed ≤ 5%. That selection is
  the only tuning here; its S3-test read needs its own pre-registration.
- **H3:** supported if rr-v2[EXP-B-002]'s Δ CI upper bound < 0.

## Expectations (written before running)
| Hypothesis | Expected |
|---|---|
| H1 | Questions help E0: E0-initial MRR below E0+answers |
| H2 | rr-v1 negation positive (+0.01 to +0.05) |
| H3 | rr-v2 negative |
| rr-v1[all=1] | ≈ rr-v1[neg=1] ± small (sex/age/onset added little on R1) |

## Declared residual dependencies (EVAL_PROTOCOL §8)
- **E0 knows half B**, since it was trained on the full
  `genes_to_phenotype`. That favours E0, the reference.
- **`genes-v1` weights are shared** by the generator and the KB.
- **The simulator's structure** (frequency sampling, onset gating) is shared
  with any Front A training data. It is irrelevant to Front B.

## Results
Run from commit `da1e3d7` (the pre-registration was committed first); 10.3
min, CPU. Results are in `results/EXP-S3-001/` (a ranks file per system and
`s3-v1-dev__report.json`); manifest `results-EXP-S3-001-s3-v1-dev`.

**The interview:** 10,210 S3-dev patients, with 6.88 questions per case on
average, of which 0.75 were answered "yes" and 6.13 "no".

Δ is vs E0+answers, with a paired bootstrap 95% CI resampling genes:

| System | MRR | Δ MRR | 95% CI | Harmed | Helped |
|---|---|---|---|---|---|
| E0-initial | 0.3178 | −0.0120 | | | |
| **E0+answers** | 0.3298 | 0 | | | |
| rr-v1[neg=0.5] | 0.3343 | **+0.0045** | [+0.0034, +0.0056] | 0.040 | 0.168 |
| rr-v1[neg=1] | 0.3376 | +0.0078 | [+0.0064, +0.0093] | 0.053 | 0.222 |
| rr-v1[neg=2] | 0.3393 | +0.0095 | [+0.0075, +0.0116] | 0.072 | 0.277 |
| rr-v1[all=1] | 0.3438 | +0.0140 | [+0.0120, +0.0159] | 0.065 | 0.289 |
| rr-v2[EXP-B-002 l2=0.1] | 0.2999 | **−0.0299** | [−0.0326, −0.0271] | **0.282** | 0.078 |
| rr-v2[without negation] | 0.3302 | +0.0004 | [−0.0004, +0.0013] | 0.069 | 0.126 |

## Verdict
- ✅ **H1:** the questions help E0 (+0.012 MRR from the "yes" answers).
- ✅ **H2**, modestly: under the pre-registered rule (CI > 0, harmed ≤ 5%),
  **rr-v1[neg=0.5] is selected, Δ +0.0045 [+0.0034, +0.0056], harmed 4.0%**.
  Higher weights gain more but harm more than 5%. When a patient's "no"
  answers come from asking about the candidates' features, penalising genes
  that annotate the denied findings helps.
- ✅ **H3**, strongly: rr-v2's R1-learned weights *hurt*, Δ −0.030, harming
  28% of patients. This confirms that its R1 gain (EXP-B-002) was the
  reporting pattern, and that deploying it would have been harmful.
- **The next step for H2 is a separate pre-registration** of the S3-test
  read of rr-v1[neg=0.5] (a Phase 4 gate), together with its R1-test
  no-regression check.

## Addenda

### 2026-09-29, Addendum 1: S3 v1 is fair for negation, NOT for sex, age or onset (limitation)
`annot-split-v1` holds out only **phenotype** annotations (aspect P). Several
things are shared by the generator and the systems' KB:
- the onset (aspect C, Orphanet ages) and inheritance (aspect I, ClinGen)
  knowledge that drives the simulator's age and sex;
- the `genes-v1` weights.

So rr-v1[all=1]'s extra +0.006 over the negation-only variant is at least
partly **circular**, and is not evidence about sex, age or onset. Evaluating
those fairly on S3 would need a v2 split that also holds out, per disease,
the onset and inheritance facts the generator uses. That is recorded as
future work; nothing is claimed from rr-v1[all=1].
